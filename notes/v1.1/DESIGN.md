本次修订：按已完成的开发实验结果选择 G1 作为下一轮基础，新增 G6（16 → 32 → 最多 48 的自适应补采样）与 G7（固定一次采样 48 条的对照）；两组都保留 G1 的官方目标切换与尾窗最小距离评分。

## 1. 目标与范围

第一轮 G0–G5 验证两个问题：当真实执行偏离参考视频的操作顺序后，严格的子目标切换是否限制后续进展；只评价 8 秒预测终点，是否漏掉候选中途接近目标的行为。先分别改目标选择和候选评分，再测试两者组合。下一轮 G6/G7 在 G1 上比较按需补采与固定增加候选数的效果及成本。

只做 planning，沿用冻结的官方 encoder、world model 和 diffusion policy。TA 已确认：**保留官方每 8 秒一张的 subgoal 序列**，不重采样目标图片或改动下载文件。改变的是如何使用已有目标，不是目标文件的时间间隔。

所有组固定 `generate=16`、`execute=1`、`n_steps=10`、`lag=0`、`tau=0.25`。一个 block 为 5 个 control steps，即 0.5 秒；每轮预测 8 秒，只执行前 0.5 秒后重新观测、重规划。G0–G5 每轮固定 16 条候选；G6 每批 16 条、最多累计 48 条；G7 每轮一次采样 48 条。环境循环、相机和任务计数沿用 Phase 1。

有限补采样只在 G6 引入，G0–G5 的定义与历史结果保持不变。warm start、CEM/MPPI、改变 horizon 或 execute 留到 G6/G7 之后。不把动作裁剪等细节作为本轮单独的 ablation。

### 3.1 统一距离定义

记当前真实 latent 为 z，当前目标为 g_m，第 n 个候选在第 h 个 block 后的预测为 z_hat[n,h]，其中 h=1…16。

```text
D[n,h] = ||z_hat[n,h] - g_m||²
T[m]   = tau * ||g_m - g_(m-1)||²
```

首目标的前一状态使用 episode 的官方 init frame。维持 baseline 的 latent 空间和平方 L2 定义，不另加 latent 归一化或任务权重。

### 3.2 G0 / G1 / G2：仅替换评分

```text
G0: C[n] = D[n,16]
G1: C[n] = min(D[n,13], D[n,14], D[n,15], D[n,16])
G2: C[n] = (D[n,13] + 2*D[n,14] + 3*D[n,15] + 4*D[n,16]) / 10
best = argmin_n C[n]
```

尾窗固定为最后 4 个 blocks，对应预测的 6.5、7、7.5、8 秒。G2 给较晚帧更大权重，避免“时间衰减”方向含糊。两组均执行选中候选的第一个 block，不能跳到最佳预测帧对应的动作。

G1 可能奖励预测中的一次偶然接近；G2 可能惩罚“先到达当前目标、随后合理离开”的计划，因此分别测试。先不扫不同尾窗和权重，也不加入额外平滑项。

额外记录每个选中候选在完整 16 步中的最接近时刻。若有大量接近发生在尾窗之前，再决定下一轮是否测试完整 horizon 的评分，不在本轮顺带扩展。

### 3.3 G3：停滞后单向向前对齐，保留作对照

优先保留官方的真实观测到达规则：

```text
||z - g_m||² < T[m]  =>  按官方规则推进目标
```

只有 active goal 长时间不变、真实距离也不再明显改善时，才检查接下来少量已有目标。**不能因为 imagined trajectory 接近了未来目标，就直接更新实际 active goal。**

以下为第一版 pilot 默认值；只在 pilot 中排除明显异常或确认定义，正式批量前写入配置并锁定：

| 参数 | 默认值 |
| --- | --- |
| 当前目标最短停留 | 24 秒 |
| 停滞观察窗口 | 最近 8 秒的真实观测 |
| 明显改善 | 窗口末 4 次距离的中位数，比窗口首 4 次下降至少 10% |
| 向前搜索范围 | 当前目标之后最多 3 个已有目标 |
| 重新匹配的确认 | 连续 3 次真实观测匹配同一个未来目标 |

具体流程：

1. 每次收到真实观测，先执行官方目标切换。正常切换后，清空旧目标的停滞记录与待确认匹配。
2. 若停留未满 24 秒，或最近 8 秒仍有至少 10% 的距离改善，使用原目标。
3. 否则，对 `m+1…min(m+3, last)` 计算 `q[j] = ||z-g_j||² / T[j]`。只把 `q[j] < 1` 视为真实匹配；阈值为零的目标不参与这条额外匹配，原始到达规则保持不变。
4. 在匹配目标中取 q 最小者；相同时取较早目标。连续 3 次观测确认同一目标 j 后，将索引向前对齐到 j，再应用官方的到达推进规则。
5. 记录本次跳转及其依据，并重新开始目标停留计时。不得回退；无未来目标满足条件时，保留当前目标。

未来目标之间的参考间距不同，因此这里用相对官方到达阈值的 q，而不直接用最小原始距离选一个“最近但仍很远”的目标。跳转依据必须保留真实观测距离、阈值和确认次数。

这个版本比较保守：如果实际箱子顺序与所有未来参考图像都不同，它可能仍不触发；若目标已超前，也无法向后纠正。这些情况应分别报告，不能据此认定参考序列完全没有问题。停留时间仅用于触发检查，不作为前移依据；没有匹配时保留当前目标，不加入 timeout 强制前移。

### 3.4 G4：停滞后双向对齐

G4 保持终点评分，以及 G3 的停滞窗口、改善阈值、距离定义和连续确认次数。主要区别是：**在当前索引周围向前、向后搜索，允许纠正已经超前的目标。** 搜索范围以当前 active index 为中心，不以历史最大索引为下界。

```text
搜索窗口 W = [max(0, m-3), min(last, m+3)]
q[j] = ||z - g_j||² / T[j]
```

具体流程：

1. 正常情况下保留官方的真实观测到达规则。目标发生正常切换后，重置停滞记录和待确认匹配。
2. 与 G3 相同，当前目标停留至少 24 秒、最近 8 秒没有至少 10% 的距离改善时，才触发附近目标搜索。
3. 搜索 W 中阈值非零的目标，比较真实观测的 q。保留当前目标作为比较项；候选须满足 `q[j] < 1`，才能作为合格匹配。无合格匹配时保持当前目标。
4. 选择 q 最小的匹配。若距离相同，优先当前目标，其次优先索引改变量较小者，再相同时取较早索引。若最佳仍为当前目标，不切换。
5. 同一个非当前目标连续 3 次真实观测被选为最佳匹配后，直接将 active index 设为 j。`j > m` 是前进，`j < m` 是回退；不设“曾到达的索引不能再访问”的限制。
6. **该轮用重对齐后的 j 进行候选评分，不在同一次调用中再次套用官方前进 while，避免立即撤销回退。** 从下一次新的真实观测开始，再判断正常到达与推进。每次前进或回退都重新计时、清空确认状态，防止沿用旧窗口连续触发。

G4 保留与 G3 相同的真实匹配门槛，先比较单向和双向搜索；不同时放宽为“选最近但仍很远的目标”。若两侧都没有匹配，应报告为无合格目标，而不是自动跳过。连续确认和重置停滞记录用于抑制来回切换；是否仍有振荡，必须从真实视频和目标切换日志检查。

**G3、G4、G5 均不使用“超时后前移一个目标”的恢复规则。** 超时只触发匹配检查，不能独立触发索引变化。真实观测匹配与官方到达规则之外，不用 imagined rollout 或 elapsed time 强行推进。

### 3.5 G5：双向对齐与评分组合

锁定 G1/G2 中较好的评分后，与 G4 的双向目标对齐组合，其他设置不变。G5 必须使用新 G4，不能使用 G3 的单向搜索。与 G4 比较评分带来的增量，与所选 G1/G2 比较双向目标对齐带来的增量。

### 3.6 G6：基于 G1 的有限补采样

G6 完整沿用 G1 的官方目标切换、16-block horizon、尾窗最小距离评分与 execute=1，**不加入 G3/G4/G5 的目标重对齐**。候选由冻结的 policy 生成，WM 对每批候选做预测和评分。

每次真实观测到来后，先按官方规则确定 active goal，再固定该轮的真实 latent z、目标 g_m、阈值 T[m] 和模型上下文。定义：

```text
D_now  = ||z - g_m||²
C[n]   = min(D[n,13], D[n,14], D[n,15], D[n,16])
C_best = 所有已采候选的最小 C[n]
r      = (D_now - C_best) / max(D_now, 1e-8)
```

r 是模型预测的距离平方相对改善率，不是任务成功概率，也不代表即将执行的第一个 block 就会实现相同比例的改善。固定 `min_improvement=0.20`，不在本轮批量结果出来后调参。

在累计 16 或 32 条候选后，只有以下两条同时成立才补采下一批 16 条：

```text
C_best >= T[m]      # 预测尾窗最小距离尚未低于到达阈值
r < 0.20           # 同时，预测改善不足 20%
```

等价地，只要 `C_best < T[m]` 或 `r >= 0.20`，便停止补采。到达累计 48 条时无条件结束搜索。D_now 已小于等于 1e-8 时不补采，避免近零距离下的比例判断不稳定。阈值为零时，`C_best < T[m]` 不成立，按改善率与预算决定是否继续。

```text
采样并评分第一批 16 条，保存最佳候选
若已达预测阈值，或预测改善率 >= 20%：返回最佳候选的第一个 block

补采并评分第二批 16 条，从全部 32 条中保留最佳
若已达预测阈值，或预测改善率 >= 20%：返回最佳候选的第一个 block

补采并评分第三批 16 条，从全部 48 条中保留最佳
返回最佳候选的第一个 block
```

已有候选不会丢弃，只有新候选需要新增 rollout；相同 cost 时保留较早采到的候选。每批使用同一真实观测和同一目标，不执行中间动作、不更新目标索引，也不把 imagined latents 加入真实历史。追加应在同一次规划调用内完成，不能通过重复调用 agent.step 来补采，避免重复更新真实上下文。

T[m] 沿用 baseline 的真实子目标到达阈值，但“预测 cost 低于它则停止补采”是本实验新增的启发式。G1 的 min cost 低于阈值，只表示尾窗中至少一帧预测满足条件，不保证到达后持续保持，也不能据此推进实际目标。

预算耗尽后，即使最佳候选仍预测变差，也返回全体候选中最好的第一个 block，不无限等待，不用 timeout 强制切换 subgoal。若 WM 预测乐观但真实执行仍停滞，这条补采条件可能不触发，应作为方法局限报告。

### 3.7 G7：基于 G1 的一次性 48 候选对照

G7 同样只使用 G1 的官方目标切换和尾窗最小距离评分。每轮固定一次 policy.sample 生成 48 条候选，用一次 batched WM rollout 预测，选 48 条中 cost 最小者，执行其第一个 block。没有改善率触发条件或分批提前停止。

G7 与 G6 的最大候选预算相同，但 G6 可用 16 或 32 条提前结束，并有串行补采开销；不能假设 G6 耗时必然更低，也不能把两者称为固定计算量相同的实验。实际候选总数、模型调用批次数与决策耗时都要报告。

两组使用相同 scene / sampler seeds 和运行环境；不同 batch 形状可能改变随机数消耗或数值结果，不默认 G7 的前 16 条与 G6 第一批逐元素一致。配对统计以同一 scene / seed 的任务结果为单位。

以上所有组均不读取 evaluator 的箱子身份、接触、位置或堆叠计数来选择目标或动作。这些信息只用于评价和视频解释。

## 4. 执行顺序

### 第一步：实现与基线一致性

将评分与目标选择作为独立配置接入现有 agent，默认保持 G0。runner 能明确区分 G0–G5，并把评分、单向/双向搜索范围、停滞条件和确认次数写入 run.json；不启用 timeout 前移。使用新的协议标识和输出目录，不能让新 G4 覆盖或续跑旧组合组 G4，也不能覆盖旧 B1 目录。

在相同 seed 和伪模型的检查中，确认 G0 的动作、RNG 消耗、目标索引和模型调用次数保持不变。用简单构造轨迹核对 G1/G2 的最优候选，保留 G3 的单向切换检查；新增 G4 的前进、回退、边界、连续确认、reset、同轮不撤销回退，以及超时但无匹配时保持目标的检查。G5 验证使用双向对齐与锁定的评分。只测试这些会影响结论的行为，不扩展为实现细节的测试清单。

### 第二步：固定 pilot

先固定场景 `100038、100069、100078、100152`，每个使用 seeds `0、2、3`，共 12 episodes / 组。这些场景均来自原 20 场景清单；pilot 仅用于检查行为和选择下一步配置，不作为独立测试集。

按 G0 → G1 → G2 → G3 → G4 的顺序比较。已有兼容的 G0–G3 pilot 可以复用；先补新 G4 的单条检查，再完成相同的 12 episodes。优先查看：100038 的目标长期停滞是否缓解；100069 已经能够继续堆叠的行为是否受损；G4 是否能纠正目标超前，是否出现来回切换或退回已完成阶段；其余案例是否仅仅目标距离更低而没有任务改善。

用 pilot 的任务结果选择 G1/G2 中较好者；若基本持平，优先 G2 作为较保守的多帧评分。G5 使用锁定后的新 G4 配置与所选评分，先在相同 pilot 检查组合行为。若复用旧的评分选择，须确认 pilot 输入、评分定义与环境一致；旧组合组的结果不自动视为 G5。

### 第三步：完整配对比较

对固定 20 scenes × seeds 0、2、3，运行 G1、G2、G3、G4、G5，每组 60 episodes。保留 G0 原始 60 次作为比较；同一环境下的 G0 pilot 若出现差异，先核对 GPU、dtype、依赖、checkpoint 与代码。环境无法一致时，应在新环境重跑完整 G0，不能将轨迹差异归因于 planner。已有兼容的 G1–G3 完整运行可复用，但不能混入配置包含 timeout 前移的结果。

各组固定同一运行环境、worker 数和视频设置。先完整收集结果，再解释收益；不因某组 pilot 表现较差而替换其 scene 或 seed。每个组都保留失败案例。

G0、G1、G2、G3 分别提供原始行为、评分改动和单向目标对齐的对照；G4−G3 检查双向搜索的效果，G5 检查组合效果。若 G5 使用 G1，也可比较 G5−G4 与 G1−G0，检查评分和双向目标对齐是否互补。

### 第四步：新增 G6/G7 的配对比较

以上 G0–G5 的完整实验已经完成，保留原始结果。本次只新增 G6/G7，不重新选择 G5 评分或重跑全部旧组。

1. 先实现 G6/G7。检查触发条件的 AND 关系、阈值与 20% 边界、16/32/48 上限、保留跨批最优候选、只执行第一个 block，以及补采过程中真实历史和目标不变。关闭补采或将预算限制为 16 的 G6 应能保持 G1 的动作、RNG 和模型调用行为。G7 检查每轮固定一次生成 48 条。
2. 在固定 pilot 场景 `100038、100069、100078、100152` × seeds `0、2、3` 上先做单条检查，再各完成 12 episodes。与兼容的 G1 pilot 比较，确认补采率、成本与视频行为；20% 阈值不按 pilot 排名反复调整。
3. 锁定实现和配置，在原 20 scenes × seeds `0、2、3` 上各运行 60 次 G6/G7，共新增 120 个 full episodes；pilot 另计 24 个。复用 `bidir-1498961` 的 60 次 G1 作为配对基础，前提是运行环境、模型、目标、任务与未改动的 G1 行为一致。
4. 沿用该批的 2080 Ti / float16 encoder 推理口径，以及一致的 worker 数、视频和计时设置。若无法保持兼容，先在新环境补齐 G1 对照，不混用早期 L40 / bfloat16 的 B1。不要因 48 条候选的开销单独改变某组的环境或任务长度。
5. 报告 `G6−G1`（按需补采）、`G7−G1`（固定增大候选集）、`G6−G7`（自适应预算与固定预算）三组配对差异。G6/G7 均以 G1 为基础，不套用 G4 双向对齐。

## 5. 评价与必要记录

主要指标沿用 Phase 1：

- mean peak boxes、达到至少 2 / 3 箱的无条件比例，以及 mean final count。
- 达到第一箱后继续达到第二箱的比例；同时给出第一箱、第二箱的无条件比例，保留分母变化。
- 第一箱到第二箱的时间，以及未到第二箱案例的剩余观察时间。不能把未完成者删除后，用成功者平均耗时代表所有案例。
- 每轮决策耗时的 mean / P95，保持相同计时和 GPU 同步口径。

G6/G7 额外比较平均每轮候选数、16/32/48 条的轮次分布、第二/第三批补采率，以及实际 policy / rollout 调用批次数。结合任务指标与决策耗时评价 G6 相对 G7 的取舍，不仅比较 latent cost。报告新增批次使最佳 cost 降低的幅度和最终选中候选来自哪一批，帮助判断额外采样是否被利用。

按相同 scene / seed 做配对差异，列出改善、持平、退步的 episode 数。三次 sampler seed 不是 60 个独立场景；如提供误差条或 bootstrap，按 scene 整组重采样。

人工只检查少量有代表性的改善、无效和退步案例，重点看第一箱后是否更早开始接近、抓取、抬起另一箱，以及是否反复操作已放好的箱子。不为此新建大规模逐帧标注任务。

复用现有日志和视频，只补支撑本轮结论的字段：

| 记录 | 用途 |
| --- | --- |
| 协议版本、variant、评分方式、尾窗与权重、单向/双向搜索实际配置 | 明确新旧 G4/G5 定义，支持复现 |
| 每个候选最终 cost；选中候选的 16 步目标距离 | 确认新评分确实影响选择 |
| 选中候选全 horizon / 尾窗的最近时刻 | 判断接近是否发生在终点前或尾窗外 |
| goal change 的原因、前后索引、真实匹配距离和阈值、前进/回退方向 | 区分正常达到、向前对齐与向后对齐，定位来回切换 |
| 每轮是否满足停滞条件、搜索窗口内目标是否有合格匹配 | 区分未触发、缺少可匹配目标和触发后无收益 |
| G6/G7 的 batch size、最大预算、20% 阈值与实际候选总数 | 明确固定预算和自适应预算，支持成本比较 |
| D_now、T[m]、每批后的全局 C_best / r、停止原因 | 核对触发条件，区分预测达标、改善足够和预算耗尽 |
| 每批最优 cost、最终选中批次、policy / rollout 调用批次数 | 判断追加候选的收益与串行调用成本 |

常规不增加完整候选动作或全部 latent 张量；必要时仅为诊断案例保存。G6/G7 的候选评分日志覆盖该轮实际采到的全部候选，不能在后处理中仍假定恰好 16 条。日志读取本身不得改变采样 RNG 或额外调用模型；G6/G7 设计内新增的采样与 rollout 正常计入成本。目标距离更低、索引走得更快仅作机制证据，**任务表现改善才算收益**。

复用旧 G0 时，清楚记录其源目录和 manifest 哈希，不复制或伪装为同一次新运行。run.json 记录代码 commit、工作区是否有未提交改动、三个输入文件 SHA256、完整场景/seed、实际算法参数、GPU/dtype 和依赖版本。新协议须明确 `G4 = 双向对齐 + 终点评分`、`G5 = 双向对齐 + 所选评分`；旧协议中的 G4 是单向对齐组合组，不能合并统计，也不能仅改目录名充当新组。

G6/G7 使用独立的新协议和运行目录；manifest 明确 `base_variant=G1`、`scoring=tail_min`、官方目标切换、各组采样模式及预算。引用既有 G1 时保存源目录、协议标识与输入哈希；不要修改 `bidir-1498961` 的 manifest、selection.json 或 episode 证据。报告可复用旧 G1，但应清楚标记来源。

原始 60 次 B1 常规日志只存各候选的终点评分，不足以离线重算 G1/G2 的决策或闭环收益。新的评分必须重新运行；单次 open-loop 张量可以辅助检查公式，不能代替闭环实验。

文档和代码在本地修改；GPU 实验在 cluster 或 Colab 执行，结果保存到新目录后同步回本地。不要修改旧实验的 run.json 或原始 episode 证据。

## 7. 本轮之后再做什么

先根据 G0–G5 判断主要瓶颈：若评分有收益，继续研究完整轨迹或多目标评分；若 G4 相对 G3 有收益，继续研究双向参考对齐；若两类改动都不明显，检查候选覆盖与模型预测偏差，不继续堆叠评分项。目标回退本身不算退步，应结合后续真实任务进展判断。

有限补采样已纳入本次新增的 G6，固定 48 条对照纳入 G7。先完成 G1/G6/G7 的收益与成本比较，再决定是否继续调整候选覆盖或搜索方式；本轮不额外扫描预算上限、20% 阈值或加入 CEM。

warm start 和 CEM/MPPI 再分别测试。warm start 沿用已讨论的方案：执行一个 block 后，从新真实观测重新 rollout 剩余计划，再在更新后的 imagined 终点用冻结 policy 补一个 block，与新采样候选共同筛选。

## 8. 完成标准

G0–G5 已交付固定场景/seed 的配对结果及视频。本次新增交付为基于 G1 的 G6/G7、固定场景/seed 的 G1/G6/G7 任务与计算成本比较，以及能解释改善和退步的少量视频案例。没有闭环结果前，不把更低的预测 cost 或更少候选数写成已验证的任务改进。
