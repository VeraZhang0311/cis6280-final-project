# v1.1：子目标对齐与轨迹评分

日期：2026-11-03。状态：实验设计，尚未实现或运行 G1–G4。

## 1. 目标与范围

本轮验证两个问题：当真实执行偏离参考视频的操作顺序后，严格的子目标切换是否限制后续进展；只评价 8 秒预测终点，是否漏掉候选中途接近目标的行为。先分别改目标选择和候选评分，再测试两者组合。

只做 planning，沿用冻结的官方 encoder、world model 和 diffusion policy。TA 已确认：**保留官方每 8 秒一张的 subgoal 序列**，不重采样目标图片或改动下载文件。改变的是如何使用已有目标，不是目标文件的时间间隔。

本轮固定 `candidates=16`、`generate=16`、`execute=1`、`n_steps=10`、`lag=0`、`tau=0.25`。一个 block 为 5 个 control steps，即 0.5 秒；每轮预测 8 秒，只执行前 0.5 秒后重新观测、重规划。环境循环、相机和任务计数沿用 Phase 1。

有限补采样、warm start、CEM/MPPI、改变 horizon 或 execute 留到本轮之后，不混入 G1–G4。不把动作裁剪等细节作为本轮单独的 ablation。

## 2. 已有证据与解释边界

主要基线是 `outputs/diagnostics/b1-20-1497072/`：20 scenes × seeds 0、2、3，共 60 次 B1。设计和实现记录见 [Phase 1 设计](../PHASE1/DESIGN.md)、[Phase 1 结果](../PHASE1/PHASE1.md)，固定场景见 [validation-scenes-20.json](../PHASE1/validation-scenes-20.json)。

| 观测 | 本批结果 |
| --- | --- |
| 曾达到至少 1 / 2 / 3 箱 | 47 / 25 / 8，分母均为 60 |
| mean peak / final count | 1.333 / 1.083 |
| 第一箱后未到第二箱 | 22 / 47 |
| 某个非末尾子目标停留超过 60 秒 | 51 / 60 |
| 最终 active goal fraction 小于 0.5 | 43 / 60 |

scene 100038 / seed 2 在 48.4 秒达到第一箱，但到 69.5 秒才从目标 0 切换到 1，此后一直停在目标 1。相反，scene 100069 / seed 0 在目标 3 停留很久，仍达到 3 箱。因此“目标索引滞后”和“任务停滞”必须分别看，不能互相代替。

核心假设是：policy 不接收目标，只根据当前 latent 生成动作候选；planner 用参考图像 latent 选择候选。真实执行一旦采用不同的抓取或箱子顺序，可能难以再匹配某个参考中间状态。更多采样未必能修复一个已经不合适的 active goal。此假设仍需通过闭环对照验证。

`active_goal_index / (goals - 1)` 仅表示参考序列的索引进度。不同目标的原始距离也不能直接拼接成一个连续改善指标；分析距离趋势须限定同一 active goal。计数下降可能来自手接触导致 evaluator 排除箱子，不能直接解释成倒塌。

旧的 `scene100038-1496824` 和 [my_diagnoses.md](../PHASE1/my_diagnoses.md) 属于另一批 A10 实验，仅作历史观察，不并入这 60 次统计。

补充证据见 [单次 open-loop 诊断](../PHASE1/OPENLOOP_POSTFIRST.md)：43 个有效窗口中，14 个曾在中途满足固定目标 latent 阈值、但终点已离开。这支持检查时序评分，但其起点为重新生成、GPU/dtype 也不同，不能作为新 planner 的闭环收益证据。

## 3. 实验矩阵

| 组别 | 子目标选择 | 候选 cost，越小越好 | 要验证的问题 |
| --- | --- | --- | --- |
| G0 | 官方规则 | 最后一个预测 latent 的距离 | 基线，已有 B1 |
| G1 | 官方规则 | 最后 4 个预测 latents 的最小距离 | 终点是否漏掉提前到达 |
| G2 | 官方规则 | 最后 4 个预测 latents 的加权平均距离 | 多帧评价是否更稳 |
| G3 | 停滞后用真实观测重新对齐 | 终点距离 | 严格目标切换是否构成瓶颈 |
| G4 | 与 G3 相同 | G1/G2 中较好的评分 | 目标选择与评分是否互补 |

G4 的评分方式只根据预先固定的 pilot 选择，随后锁定。完整 60 次比较用于报告各组表现，不再针对这些结果反复调权重或停滞阈值。

### 3.1 统一距离定义

记当前真实 latent 为 z，当前目标为 g_m，第 n 个候选在第 h 个 block 后的预测为 z_hat[n,h]，其中 h=1…16。

```text
D[n,h] = ||z_hat[n,h] - g_m||²
T[m]   = tau * ||g_m - g_(m-1)||²
```

首目标的前一状态使用 episode 的官方 init frame。维持 baseline 的 latent 空间和平方 L2 定义，不另加 latent 归一化或任务权重。

### 3.2 G0 / G1 / G2：仅替换评分

```text
G0: C[n] = D[n,16]
G1: C[n] = min(D[n,13], D[n,14], D[n,15], D[n,16])
G2: C[n] = (D[n,13] + 2*D[n,14] + 3*D[n,15] + 4*D[n,16]) / 10
best = argmin_n C[n]
```

尾窗固定为最后 4 个 blocks，对应预测的 6.5、7、7.5、8 秒。G2 给较晚帧更大权重，避免“时间衰减”方向含糊。两组均执行选中候选的第一个 block，不能跳到最佳预测帧对应的动作。

G1 可能奖励预测中的一次偶然接近；G2 可能惩罚“先到达当前目标、随后合理离开”的计划，因此分别测试。先不扫不同尾窗和权重，也不加入额外平滑项。

额外记录每个选中候选在完整 16 步中的最接近时刻。若有大量接近发生在尾窗之前，再决定下一轮是否测试完整 horizon 的评分，不在本轮顺带扩展。

### 3.3 G3：停滞后重新对齐

优先保留官方的真实观测到达规则：

```text
||z - g_m||² < T[m]  =>  按官方规则推进目标
```

只有 active goal 长时间不变、真实距离也不再明显改善时，才检查接下来少量已有目标。**不能因为 imagined trajectory 接近了未来目标，就直接更新实际 active goal。**

以下为第一版 pilot 默认值；只在 pilot 中排除明显异常或确认定义，正式批量前写入配置并锁定：

| 参数 | 默认值 |
| --- | --- |
| 当前目标最短停留 | 24 秒 |
| 停滞观察窗口 | 最近 8 秒的真实观测 |
| 明显改善 | 窗口末 4 次距离的中位数，比窗口首 4 次下降至少 10% |
| 向前搜索范围 | 当前目标之后最多 3 个已有目标 |
| 重新匹配的确认 | 连续 3 次真实观测匹配同一个未来目标 |

具体流程：

1. 每次收到真实观测，先执行官方目标切换。正常切换后，清空旧目标的停滞记录与待确认匹配。
2. 若停留未满 24 秒，或最近 8 秒仍有至少 10% 的距离改善，使用原目标。
3. 否则，对 `m+1…min(m+3, last)` 计算 `q[j] = ||z-g_j||² / T[j]`。只把 `q[j] < 1` 视为真实匹配；阈值为零的目标不参与这条额外匹配，原始到达规则保持不变。
4. 在匹配目标中取 q 最小者；相同时取较早目标。连续 3 次观测确认同一目标 j 后，将索引向前对齐到 j，再应用官方的到达推进规则。
5. 记录本次跳转及其依据，并重新开始目标停留计时。不得回退；无未来目标满足条件时，保留当前目标。

未来目标之间的参考间距不同，因此这里用相对官方到达阈值的 q，而不直接用最小原始距离选一个“最近但仍很远”的目标。跳转依据必须保留真实观测距离、阈值和确认次数。

这个版本比较保守：如果实际箱子顺序与所有未来参考图像都不同，它可能仍不触发。这种结果应报告为重对齐条件缺少覆盖，不能据此认定参考序列完全没有问题。纯 timeout 后强制前进一个目标属于另一种方法，若需要再单独立项，不作为 G3 隐藏 fallback。

不读取 evaluator 的箱子身份、接触、位置或堆叠计数来选择目标或动作。这些信息只用于评价和视频解释。

## 4. 执行顺序

### 第一步：实现与基线一致性

将评分与目标选择作为独立配置接入现有 agent，默认保持 G0。runner 能明确区分 G0–G4，并把所有实际参数写入 run.json；不能让新组覆盖旧 B1 目录。

在相同 seed 和伪模型的检查中，确认 G0 的动作、RNG 消耗、目标索引和模型调用次数保持不变。用简单构造轨迹核对 G1/G2 的最优候选，并检查 G3 的正常切换、连续确认、单调推进和 reset。只测试这些会影响结论的行为，不扩展为实现细节的测试清单。

### 第二步：固定 pilot

先固定场景 `100038、100069、100078、100152`，每个使用 seeds `0、2、3`，共 12 episodes / 组。这些场景均来自原 20 场景清单；pilot 仅用于检查行为和选择下一步配置，不作为独立测试集。

按 G0 → G1 → G2 → G3 的顺序运行。优先查看：100038 的目标长期停滞是否缓解；100069 已经能够继续堆叠的行为是否受损；其余案例是否出现误跳或仅仅更低的目标距离而没有任务改善。

用 pilot 的任务结果选择 G1/G2 中较好者；若基本持平，优先 G2 作为较保守的多帧评分。G4 使用锁定后的 G3 配置与所选评分，先在相同 pilot 检查组合行为。

### 第三步：完整配对比较

对固定 20 scenes × seeds 0、2、3，运行 G1、G2、G3、G4，每组 60 episodes。保留 G0 原始 60 次作为比较；同一环境下的 G0 pilot 若出现差异，先核对 GPU、dtype、依赖、checkpoint 与代码。环境无法一致时，应在新环境重跑完整 G0，不能将轨迹差异归因于 planner。

各组固定同一运行环境、worker 数和视频设置。先完整收集结果，再解释收益；不因某组 pilot 表现较差而替换其 scene 或 seed。每个组都保留失败案例。

G0、G1、G2、G3 分别提供原始行为、评分改动和目标改动的对照；G4 检查组合效果。若 G4 使用 G1，也可比较 G4−G3 与 G1−G0，检查两项改动是否互补。

## 5. 评价与必要记录

主要指标沿用 Phase 1：

- mean peak boxes、达到至少 2 / 3 箱的无条件比例，以及 mean final count。
- 达到第一箱后继续达到第二箱的比例；同时给出第一箱、第二箱的无条件比例，保留分母变化。
- 第一箱到第二箱的时间，以及未到第二箱案例的剩余观察时间。不能把未完成者删除后，用成功者平均耗时代表所有案例。
- 每轮决策耗时的 mean / P95，保持相同计时和 GPU 同步口径。

按相同 scene / seed 做配对差异，列出改善、持平、退步的 episode 数。三次 sampler seed 不是 60 个独立场景；如提供误差条或 bootstrap，按 scene 整组重采样。

人工只检查少量有代表性的改善、无效和退步案例，重点看第一箱后是否更早开始接近、抓取、抬起另一箱，以及是否反复操作已放好的箱子。不为此新建大规模逐帧标注任务。

复用现有日志和视频，只补支撑本轮结论的字段：

| 记录 | 用途 |
| --- | --- |
| variant、评分方式、尾窗与权重、G3 实际配置 | 明确组别，支持复现 |
| 每个候选最终 cost；选中候选的 16 步目标距离 | 确认新评分确实影响选择 |
| 选中候选全 horizon / 尾窗的最近时刻 | 判断接近是否发生在终点前或尾窗外 |
| goal change 的原因、前后索引、真实匹配距离和阈值 | 区分正常达到与重新对齐 |
| 每轮是否满足停滞条件、未来目标是否有合格匹配 | 区分未触发、缺少可匹配目标和触发后无收益 |

常规不增加完整候选动作或全部 latent 张量；必要时仅为诊断案例保存。日志读取不得改变采样 RNG 或额外调用模型。目标距离更低、索引走得更快仅作机制证据，**任务表现改善才算收益**。

## 6. 输出与复现

建议新 runner 输出：

```text
outputs/planning/v1.1/<run-id>/
  run.json
  summary.json
  G0/episodes/scene-<scene>.sample-<seed>/...
  G1/episodes/...
  G2/episodes/...
  G3/episodes/...
  G4/episodes/...
  analysis/
```

复用旧 G0 时，清楚记录其源目录和 manifest 哈希，不复制或伪装为同一次新运行。run.json 记录代码 commit、工作区是否有未提交改动、三个输入文件 SHA256、完整场景/seed、实际算法参数、GPU/dtype 和依赖版本。

原始 60 次 B1 常规日志只存各候选的终点评分，不足以离线重算 G1/G2 的决策或闭环收益。新的评分必须重新运行；单次 open-loop 张量可以辅助检查公式，不能代替闭环实验。

文档和代码在本地修改；GPU 实验在 cluster 或 Colab 执行，结果保存到新目录后同步回本地。不要修改旧实验的 run.json 或原始 episode 证据。

## 7. 本轮之后再做什么

先根据 G0–G4 判断主要瓶颈：若评分有收益，继续研究完整轨迹或多目标评分；若 G3 有收益，研究更可靠的参考对齐；若两者都不明显，检查候选覆盖与模型预测偏差，不继续堆叠评分项。

有限补采样作为下一轮独立实验：候选由 policy 生成，WM 只负责预测和评价。若触发补采样，保留已有最优候选，设置 16 → 32 → 最多 48 的上限，并与一次采样 48 个的预算对照。触发应考察相对当前观测的预测改善，而非直接要求 8 秒终点满足严格到达阈值；不能无限等待且不返回动作。

warm start 和 CEM/MPPI 再分别测试。warm start 沿用已讨论的方案：执行一个 block 后，从新真实观测重新 rollout 剩余计划，再在更新后的 imagined 终点用冻结 policy 补一个 block，与新采样候选共同筛选。

## 8. 完成标准

本轮交付是可独立开关的评分与目标对齐、固定场景/seed 的 G0–G4 配对结果，以及能解释改善和退步的少量视频案例。没有闭环结果前，不把这份设计或更低的 latent cost 写成已验证的改进。
